# Decisions

## D001. Configuration in markdown tables, not csv or json (2026-10-30)
Context: study-specific data had been hard-coded in the HTML or read from csv files built out of Excel workbooks.
Decision: six markdown files in `config/`, each holding pipe tables found by their heading.
Alternatives rejected: json (no room for explanation beside the values, error-prone by hand); csv (one table per file, no documentation alongside); yaml (needs a parser library).
Consequence: the files read as documentation on GitHub and can be reviewed in a diff. Cells cannot contain `|`.
Status: active

## D002. Result files found by declared patterns (2026-10-30)
Context: the CVF build accepted two fixed name forms, and a model with other scenario codes needed code changes.
Decision: `config/results.md` lists path patterns with `{iso3}` and `{scenario}` tokens; tokens match only listed codes, longest first.
Alternatives rejected: guessing country and scenario from any token in the path (the CVF approach; ambiguous once codes are user-defined).
Consequence: unknown codes are refused, never guessed. A user with an existing layout writes a pattern instead of renaming files.
Status: active

## D003. Scenario = case x variant, rate from config (2026-10-30)
Context: the CVF build parsed REF/NZE and LDR/MDR/CDR out of the scenario code.
Decision: `config/scenarios.md` gives each code its case, variant and rate, with country overrides.
Alternatives rejected: a naming convention parsed by regex (breaks for any other study).
Consequence: the discount-rate views work for any number of cases and variants; a scenario with no rate is skipped there, not given a default.
Status: active

## D004. No built-in data (2026-10-30)
Context: the CVF build shipped a sample, country profiles, silhouettes and a rate table inside the HTML.
Decision: remove them; the page is empty until a folder with `config/` is linked.
Alternatives rejected: keeping a sample in the HTML (a second source of truth that can disagree with config).
Consequence: placeholder results live in `results/` and are regenerated by a seeded script. Country markers are drawn generically.
Status: active

## D005. Playwright for tests only (2026-10-30)
Context: the dashboard runs in a browser and its logic is inside the page.
Decision: tests drive the real page with Playwright (dev dependency, pinned to the tested version 1.63.0).
Alternatives rejected: extracting the functions into a module for Node tests (would split the single file the users download).
Consequence: running the tests needs Node and Chromium; using the dashboard needs neither.
Status: active

## D006. Synthetic placeholder results, ISO user-assigned codes (2026-10-30)
Context: the repository must show the tool working without publishing real study data.
Decision: three invented countries, codes XAA to XAF (ISO 3166-1 user-assigned range), coordinates near real places only to spread the markers; results from a deterministic rule-based script.
Alternatives rejected: real results (not publishable); random noise (charts would show no readable structure).
Consequence: every placeholder file says it is synthetic in its second line.
Status: active

## D007. Browser storage names of its own (2026-10-30)
Context: 0.1.0 reused the CVF dash's IndexedDB name and localStorage keys. All file:// pages share one storage origin in Chrome and Edge, so Refresh re-read the folder linked in the CVF dash.
Decision: "osemosys-dash" for IndexedDB, "osd-" for every other key.
Alternatives rejected: a per-file key derived from the page path (breaks when the file is moved or renamed).
Consequence: a user upgrading from 0.1.0 links the folder once more; comments cached by the CVF dash no longer appear here.
Status: active
